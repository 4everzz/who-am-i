Prompt 改了没人知道，比改错更麻烦

2026-10-27 · 项目二 · 智愿通

有一周评测分数突然掉了三个点，排查了半天代码、模型、数据，最后发现是有人改了一句 Prompt 里的措辞。改动没有记录，也没有人知道。

一、Prompt 是代码，不是配置

它的影响比大多数代码更大：改一个形容词可能让拒答率翻倍。但它通常以字符串常量的形式散在业务文件里，没有 diff、没有 review、没有版本号。

二、拎出来的三个动作

  • 独立文件：每个 Prompt 一个模板文件，带变量占位符，不再拼字符串。
  • 版本号 + 指纹：模板内容算哈希，评测报告里记录用了哪一版。分数对不上版本，等于没测。
  • 改动走 review：和代码一样提 PR，改动理由写在提交信息里。

三、报告要能追溯

现在的评测报告开头会打印四个指纹：评测集版本、Prompt 版本、模型名、被测代码的 commit。任何一个变了，报告自动标记为「不可比」，不能拿来和上一版做对比。

能回滚的前提是知道回滚到哪一版。Prompt 没有版本号，回滚就是凭记忆改回去。

这套东西不复杂，加起来不到两百行，但它把「感觉变差了」变成了「v3 到 v4 之间，拒答率涨了 4 个点」。前者没法行动，后者可以直接定位。
